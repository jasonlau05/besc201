Shortest-Job-First (SJF) Scheduling
• Associate with each process the length of its next CPU burst
•  Use these lengths to schedule the process with the shortest time
• SJF is optimal – gives minimum average waiting time for a given set 
of processes
• The difficulty is knowing the duration of the next CPU request
• Could ask the user or determine a good estimate
• Preemptive version called shortest-remaining-time-first
• Preemptive refers to a scheduler where OS takes the process out of the 
CPU before it completes.
We will look at preemptive schedulers soon.

=== PDF PAGE 28 ===
Round Robin (RR)
• Each process gets a small unit of CPU time (time quantum q), usually 
10-100 milliseconds.  After this time has elapsed, the process is 
preempted and added to the end of the ready queue.
• If there are n processes in the ready queue and the time quantum is q, 
then each process gets 1/n of the CPU time in chunks of at most q time 
units at once.  No process waits more than (n-1)q time units.
• Timer interrupts every quantum to schedule next process
• Performance
• q large  FIFO
• q small  q must be large with respect to context switch, otherwise overhead is 
too high
• ‘time slice’ is a better term than ‘time quantum’

Priority Scheduling
• A priority number (integer) is associated with each process
• The CPU is allocated to the process with the highest priority
(smallest integer  highest priority)
• Preemptive
• Nonpreemptive
• SJF is priority scheduling where priority is the inverse of predicted next 
CPU burst time
• Problem: Starvation – low-priority processes may never execute
• Solution: Aging – as time progresses increase the priority of the process

Multilevel Feedback Queue
• A process can move between the various queues.
• Multilevel-feedback-queue scheduler defined by the 
following parameters:
• Number of queues
• Scheduling algorithms for each queue
• Method used to determine when to upgrade a process
• Method used to determine when to demote a process
• Method used to determine which queue a process will enter when 
that process needs service
• Aging can be implemented using multilevel feedback queue

=== PDF PAGE 42 ===
Example of Multilevel Feedback Queue
• Three queues: 
• Q0 – RR with time quantum 8 milliseconds
• Q1 – RR time quantum 16 milliseconds
• Q2 – FCFS
• Scheduling
• A new process enters queue Q0 which is served in 
RR
• When it gains CPU, the process receives 8 
milliseconds
• If it does not finish in 8 milliseconds, the process  is 
moved to queue Q1
• At Q1 job is again served in RR and receives 16 
additional milliseconds
• If it still does not complete, it is preempted and 
moved to queue Q2

Multiple-Processor Scheduling (cont)
• Symmetric multiprocessing (SMP) is where each processor is 
self scheduling.
• All threads may be in a common ready queue
• Each processor may have its own private queue of threads 


=== PDF PAGE 46 ===
Multiple-Processor Scheduling – Load Balancing
• If SMP , need to keep all CPUs loaded for efficiency
• Load balancing attempts to keep workload evenly distributed
• Push migration – periodic task checks load on each processor, and 
if found pushes task from overloaded CPU to other CPUs
• Pull migration – idle processors pulls waiting task from busy 
processor

=== PDF PAGE 47 ===
Multiple-Processor Scheduling – Processor Affinity
• When a thread has been running on one processor, the cache contents of 
that processor stores the memory accesses by that thread.
• We refer to this as a thread having affinity for a processor (i.e., “processor 
affinity”)
• Load balancing may affect processor affinity as a thread may be moved 
from one processor to another to balance loads, yet that thread loses the 
contents of what it had in the cache of the processor it was moved off of.
• Soft affinity – the operating system attempts to keep a thread running on 
the same processor, but no guarantees.
• Hard affinity – allows a process to specify a set of processors it may run 
on.

Priority-based Scheduling

• But only guarantees soft real-time

• 0 ≤ t ≤ d ≤ p
• Rate of periodic task is 1/p


=== PDF PAGE 54 ===
Rate Monotonic Scheduling
• A priority is assigned based on the inverse of its period
• Shorter periods = higher priority;
• Longer periods = lower priority
• P1 is assigned a higher priority than P2.

=== PDF PAGE 56 ===
Earliest Deadline First Scheduling (EDF)
• Priorities are assigned according to deadlines:
the earlier the deadline, the higher the priority;
 the later the deadline, the lower the priority


=== PDF PAGE 57 ===
Proportional Share Scheduling
• T shares are allocated among all processes in the system
• An application receives N shares where N < T
• This ensures each application will receive N / T of the total 
processor time

=== PDF PAGE 58 ===
POSIX Real-Time Scheduling
• The POSIX.1b standard
• API provides functions for managing real-time threads
• Defines two scheduling classes for real-time threads:
1. SCHED_FIFO - threads are scheduled using a FCFS strategy with a 
FIFO queue. There is no time-slicing for threads of equal priority
2. SCHED_RR - similar to SCHED_FIFO except time -slicing occurs for 
threads of equal priority
• Defines two functions for getting and setting scheduling policy:
1.  pthread_attr_getsched_policy(pthread_attr_t 
*attr, int *policy) 
2.  pthread_attr_setsched_policy(pthread_attr_t 
*attr, int policy)

=== PDF PAGE 60 ===
Linux Scheduling Through Version 2.5
• Prior to kernel version 2.5, ran variation of standard UNIX 
scheduling algorithm
• Version 2.5 moved to constant order O(1) scheduling time
• Preemptive, priority based
• Two priority ranges: time-sharing and real-time
• Real-time range from 0 to 99 and nice value from 100 to 140
• Map into  global priority with numerically lower values indicating higher priority
• Higher priority gets larger q
• Task run-able as long as time left in time slice ( active)
• If no time left (expired), not run-able until all other tasks use their slices
• All run-able tasks tracked in per-CPU runqueue data structure
• Two priority arrays (active, expired)
• Tasks indexed by priority
• When no more active, arrays are exchanged
• Worked well, but poor response times for interactive processes

=== PDF PAGE 61 ===
Linux Scheduling in Version 2.6.23 +
• Completely Fair Scheduler (CFS)
• Scheduling classes
• Each has specific priority
• Scheduler picks highest priority task in highest scheduling class
• Rather than quantum based on fixed time allotments, based on proportion of 
CPU time
• Two scheduling classes included, others can be added
1. default
2. real-time
• achieves proportional sharing by making virtual runtime increase 
more slowly for tasks with larger weights. It then favors the 
runnable task with the smallest virtual runtime.

=== PDF PAGE 62 ===
Linux Scheduling in Version 2.6.23 + (Cont.)
• Quantum calculated based on nice value from -20 to +19
• Lower value is higher priority
• Calculates target latency – interval of time during which task should run at 
least once
• Target latency can increase if say number of active tasks increases
• CFS scheduler maintains per task virtual run time in variable 
vruntime
• Associated with decay factor based on priority of task – lower priority is 
higher decay rate
• Normal default priority yields virtual run time = actual run time
• To decide next task to run, scheduler picks task with lowest virtual 
run time

=== PDF PAGE 63 ===
Linux Scheduling (Cont.)
• Real-time scheduling according to POSIX.1b
• Real-time tasks have static priorities
• Real-time plus normal map into global priority scheme
• Nice value of -20 maps to global priority 100
• Nice value of +19 maps to priority 139

=== PDF PAGE 66 ===
Cgroups (regarding CPU usage)
• Aims at bounding resources associated with a group of processes (e.g., 
all processes in a given application)
Concept Meaning
Group scheduling cgroups organize processes into a hierarchy so CPU resources can be allocated to an entire application, service, or container .
Weight: relative share
cpu.weight determines a group’s share when groups compete. A weight ratio 
of 2:1 means roughly twice the CPU allocation under sustained contention —
not a fixed percentage or cap.
Quota: upper limit cpu.max sets a CPU-time budget per period. Once the group exhausts its budget, it can be throttled until replenishment. 
Placement: allowed CPUs cpuset.cpus restricts where tasks can run. 

=== PDF PAGE 67 ===
Scheduling in Windows
• preemptive, priority-based thread scheduling, with round-robin 
time slicing among ready threads at the same priority
• 32 priority levels, numbered 0–31: 1–15 are the variable range, 16–
31 are the real-time range, and 0 is reserved for the zero-page 
system thread. A thread’s base priority comes from its process 
priority class and its relative thread priority.
• Priority boosts
•  temporarily boost threads following events such as I/O completion, 
improving responsiveness. 
• These boosts decay toward the base priority as time slices are completed
• threads in the real-time range do not receive these boosts.
