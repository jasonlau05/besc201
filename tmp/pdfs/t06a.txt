=== PDF PAGE 6 ===
Memory Protection
• Memory protection implemented by associating protection bit with 
each frame to indicate if read-only or read-write access is allowed
• Can also add more bits to indicate page execute-only, and so on
• Valid-invalid bit attached to each entry in the page table:
•“valid” indicates that the associated page is in the process’ logical address 
space, and is thus a legal page
•“invalid” indicates that the page is not in the process’ logical address space
• Any violations result in a trap to the kernel

Structure of the Page Table
• Memory structures for paging can get huge using straight-forward methods
• Consider a 32-bit logical address space (small for on modern 
computers):
• Page size of 4 KB (212)
• Page table would have 1 million entries (232 / 212)
• If each entry is 4 bytes ➔ each process 4 MB of physical address space for the  
page table alone
• Don’t want to allocate that contiguously in main memory
• A solution is to divide the page table into smaller units
• Hierarchical Paging
• Hashed Page Tables
• Inverted Page Tables

• x86-64 normally uses a 4-level page table. Newer processors optionally support 5-
level paging for larger virtual address spaces.
• Extension for the x86-64 line of processors that extends size of virtual addresses

=== PDF PAGE 21 ===
Hashed Page Tables
• Common in address spaces > 32 bits
• The virtual page number is hashed into a page table
• This page table contains a chain of elements hashing to the same location
• Each element contains (1) the virtual page number (2) the value of 
the mapped page frame (3) a pointer to the next element
• Virtual page numbers are compared in this chain searching for a 
match
• If a match is found, the corresponding physical frame is extracted
• Variation for 64-bit addresses is clustered page tables
• Similar to hashed but each entry refers to several pages (such as 16) rather 
than 1
• Especially useful for sparse address spaces (where memory references are 
non-contiguous and scattered)

=== PDF PAGE 23 ===
Inverted Page Table
• Rather than each process having a page table and keeping 
track of all possible logical pages, track all physical pages
• One entry for each real page of memory
• Entry consists of the virtual address of the page stored in that 
real memory location, with information about the process 
that owns that page

=== PDF PAGE 25 ===
Inverted Page Table (cont)
• Rather than each process having a page table and keeping track of all 
possible logical pages, track all physical pages
• One entry for each real page of memory
• Entry consists of the virtual address of the page stored in that real 
memory location, with information about the process that owns that 
page
• Decreases memory needed to store each page table, but increases 
time needed to search the table when a page reference occurs
• Use hash table to limit the search to one — or at most a few — page-
table entries
• TLB can accelerate access
• But how to implement shared memory?
• One mapping of a virtual address to the shared physical address

Memory segments
• Think back to circa 1980. 
• Microcomputers used physical addresses represented with 16 
bits (values 0x0000 to 0xffff, i.e., 0 to 65535). 
• So 64KB of memory.
• IBM was designing the PC and they wanted 1MB of memory: 
• go from 16 bits (i.e., 4 hexa digits) to how many?

=== PDF PAGE 28 ===
Memory segments - 2
• Inside the CPU, all the paths for data assumed addresses with 
4 hexa digits
• They represent 5 hexa using two instances of 4 hexa (so use 
two 8 bits to represent a 12 bit)
• Addresses were like 792d:12f3
• Intel added a register to store the segment (the first part), so 
instructions stayed with 16 bit addresses

=== PDF PAGE 29 ===
Memory segments - 3
• Introduced in 78 (Intel 8086) to allow programs to address more 
than 64 KB
• Intel 80286 in 1982 added virtual memory and protection
• Code segment, stack segment, data segment
• x86-64 in 2003 (by AMD) dropped segmentation 
• Intel introduced its compatible implementation Intel 64 in 2004
